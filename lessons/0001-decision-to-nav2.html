追踪一个巡逻目标

从 src/decision 出发，找到巡逻点在哪里选出来，又怎样成为 Nav2 的导航任务。

目录速查与源码入口

行为树在什么时候做决定

src/decision 下只有一个 ROS 包 bt_manager。ROS 回调接收外部状态，写入黑板（共享键值数据）。管理器反复 tick 行为树，也就是从根节点发起一次求值。main.cpp 里调用 run(30.0)，主循环目标频率是 30 Hz。每轮依次处理资源、战术模式、导航、姿态和云台。

程序入口 · 加载与 tick 顺序 · ROS 回调

先记住两条读树规则。ReactiveFallback 每轮重新从上往下试，遇到 FAILURE 就试下一项，遇到 RUNNING 或 SUCCESS 就在本轮停止往下试。普通 Sequence 按顺序执行，当前子节点成功才走下一步。如果当前子节点返回 RUNNING，下一轮在同一条序列继续时会接着 tick 它。

从 XML 追到 Nav2

在 nav_tree.xml 搜索 Priority5TrackPatrol。假设上方分支本轮都返回 FAILURE，这条巡逻分支才会被 tick。第一条巡逻序列可以压缩成四步。

CheckGameTimeWindow      检查黑板里的剩余时间是否在 301–390 秒
SelectPatrolPoint       读取巡逻索引，选点并写入 nav_goal
NavigateToPoseAction    读取 nav_goal，交给 Nav2 导航
Wait                    导航节点成功后，进入等待
  1. 判断。ROS 接口把剩余时间写成黑板键 game_time_remaining。CheckGameTimeWindow::tick() 读取它，与 XML 给出的范围比较。条件实现 · 巡逻 XML
  2. 选点。SelectPatrolPoint::tick() 用 tactical_mode 和 XML 的 patrol_branch 选点表，用 patrol_index 选出一个点，然后推进索引并把坐标写入 nav_goal。选点实现
  3. 发送。bt_manager.cpp 把 XML 标签 NavigateToPoseAction 注册为动作客户端，默认 action 名称为 navigate_to_pose。它从黑板读取 nav_goal，构造 map 坐标系下的位姿目标，由 Nav2 的 BtActionNode 基类发送。注册 · 目标封装 · Nav2 基类

巡逻分支 → 黑板 nav_goal → ROS action → Nav2

这条链里，bt_manager 负责选目的地，Nav2 接收目标并执行导航。ROS action 是长任务的接口，可以发送目标、接收反馈、获取结果，也支持取消。

首读一手资料 · ROS 2 Jazzy 的 About Actions，读到 Goal、Feedback、Result 即可回到源码。NavigateToPose 消息定义。

预测下一步

1. 巡逻序列刚进入，剩余时间是 350 秒。谁写入目标？
2. 导航返回 RUNNING。下一轮仍 tick 到同一巡逻序列，从哪继续？
核对答案

第一题是「巡逻选点节点」。第二题是「继续导航步骤」。外层优先级每轮重新评估，第二题的前提是这一轮仍然选到了同一巡逻序列。
