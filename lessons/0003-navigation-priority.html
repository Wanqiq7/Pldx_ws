在两层各追一个节点

在 nav_tree.xml 找到外层的 NavPriorityRoot。它是 ReactiveFallback，每轮从顶部检查子分支。分支返回 FAILURE 时继续往下，遇到 RUNNING 或 SUCCESS 时结束本轮筛选。高优先级分支一旦接管，仍在运行的低优先级分支会收到 halt()。BehaviorTree.CPP 实现

沿 NavPriorityRoot 找到靠近末尾的直接子分支 Priority5TrackPatrol，再往里找第一条普通 Sequence。如果它连续被选中，运行中的 NavigateToPoseAction 会继续得到 tick。如果序列被 halt()，内部索引会重置。之后再次进入该序列，从时间检查开始。导航树 XML · Sequence 实现

第一课里 nav_goal 保存巡逻目标。第二课里 current_pose 保存当前位置。下面假设上方有一个只看当前位置的示意分支。我们给定它每轮的状态，专心推演父节点的选择。

手动推演三轮

轮次上方分支巡逻序列
1FAILURE时间检查通过，选点后启动导航。导航返回 RUNNING。
2RUNNING上方分支接管，巡逻被 halt()，序列进度重置。
3FAILURE假设轮到同一条巡逻序列，它从时间检查开始。

巡逻导航节点的 halt() 会调用 Nav2 客户端基类。基类判断目标需取消时，会向 action server 发送取消请求。读日志时，可以分别确认树何时调用 halt()，以及 action 何时返回取消结果。本仓库的 halt() · Nav2 Jazzy 客户端基类

合上表格，预测下一步

1. 巡逻正在导航。下一轮，上方各分支都返回 FAILURE。巡逻接着做什么？
2. 巡逻已被上方分支中止。等同一条巡逻序列重新被选中，它从哪一步开始？
核对答案

第一题继续执行导航。第二题重做时间检查。回到 XML，用缩进指出负责重新检查优先级的外层节点，以及保留巡逻执行进度的内层节点。

如果你在实际 XML 里找到两处同名的 Priority5TrackPatrol，可以把它们各自的父节点发给我，我们一起按层级定位。
