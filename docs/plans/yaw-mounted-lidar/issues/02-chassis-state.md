# #7 — 从大 Yaw 雷达运动解析恢复实体底盘状态

**GitHub:** https://github.com/Wanqiq7/Pldx_ws/issues/7

**Label:** ready-for-agent

## What to build

新增统一底盘状态转换节点，输入原始 LIO 里程计、同期大 Yaw 反馈及完整三维安装几何，输出实体底盘参考点的位置、朝向、线速度和角速度。原始 `/aft_mapped_to_init` 继续表示雷达内置 IMU 的运动；新增 `/chassis/odom` 表示实体底盘状态。

采用已确认的几何关系：先由底盘到大 Yaw 的关节变换和转动端到 IMU 的安装变换得到当前外参，再从 LIO 位姿恢复底盘位姿。速度使用解析刚体关系，位姿差分仅用于独立验证。ROSE 的动态外参分层思路可参考，其本地动态分支的矩阵顺序不能照搬。

## Acceptance criteria

- [ ] 输入使用工单 01 冻结的反馈契约，在每个 LIO 测量时刻取得对齐的关节角和转速，明确插值与角度展开规则。
- [ ] 底盘里程计 pose 的父坐标系为 `camera_init`，child 为 `base_link`，twist 表达在 `base_link`；消息、TF 和验证工具使用相同测量时间及底盘参考点。
- [ ] 支持独立的转轴位置、关节零位/方向和转动端到 IMU 的固定三维外参；同时覆盖底盘参考点与转轴重合及不重合、雷达倾斜安装的情形。
- [ ] 角速度先变换到共同坐标系再扣关节转动，线速度同时处理底盘参考点到转轴、转轴到 IMU 的杆臂；不把倾斜 IMU 的 angular.z 直接当作世界竖直轴转速。
- [ ] 提供在隔离 ROS 域或独立 frame 前缀下可运行的节点验证入口，输出完整底盘状态及候选物理 TF，而不与现有运行链的 TF 发布者冲突；正式启用由工单 05 完成。
- [ ] 合成真值验证覆盖：底盘静止而关节转动、关节锁定而底盘旋转、两者同时运动、非零转轴偏移和倾斜安装；明确数值容差并验证位姿与 twist。包含“雷达只转 30°，底盘仍为 0°”反例。
- [ ] 修正后位姿差分按测量时间与解析速度对比，仅作为验证输出；保留原始 LIO 定位与点云语义，不新增保护状态机。
