# #8 — 让 MINCO、MPC 与 Nav2 使用统一底盘状态

**GitHub:** https://github.com/Wanqiq7/Pldx_ws/issues/8

**Label:** ready-for-agent

## What to build

使现有 MINCO 规划器、MPC 和 Nav2 停车速度检查能够使用 `/chassis/odom`，以实体底盘的位置、朝向及速度形成一致的规划控制状态，同时保留 `base_link_fake` 作为导航虚拟参考系。大 Yaw 单独扫转时，不再将雷达的转动和切向运动当成底盘运动输入控制器。

统一转换节点已经完成雷达到底盘的几何和速度恢复；消费者只按所需世界坐标系转换底盘状态，不再重复做旧雷达杆臂补偿。本工单提供独立的集成验证配置，默认整栈切换在工单 05 中统一完成。

## Acceptance criteria

- [ ] 规划器当前速度、低速时的当前 yaw、姿态相关逻辑，以及 MPC 当前 yaw/omega 和延迟补偿均采用实体底盘状态。
- [ ] Nav2 的速度观测与停车检查采用同一底盘里程计；确认虚拟零 yaw 的导航参考系不会覆盖物理底盘朝向。
- [ ] 标准 Odometry 的 child-frame twist 正确旋转到控制所需世界参考系；当前控制继续使用 `camera_init`，经 `map` 定位修正取位姿时使用一致的参考点和变换。
- [ ] 移除新底盘状态输入路径上重复的固定雷达杆臂补偿，不要求伪造旧安装偏移来使结果正确。
- [ ] 用工单 02 的合成/回放输入运行规划控制链：底盘静止大 Yaw 扫转时控制状态保持静止；底盘真实转动时状态正确跟随；非零雷达杆臂不会被扣除两次。
- [ ] 维持现有位置到达、隧道准备减速、逃逸和普通/小陀螺角速度仲裁行为；隧道命令策略继续由控制器持有，不迁移到通信边界。
- [ ] 相关包构建与有意义的包级/跨包检查通过，记录输入场景和结果；不通过新增停止保护规避状态转换问题。
